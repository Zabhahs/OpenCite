feat(v0.46): make the paid API sellable — money-path fixes, developer path, honest sources, legal pages

Product decision of record (audit docs/audit-2026-09-04): ONE paid SKU — prepaid API/MCP
credit packs. The web app stays free and unmetered (it is the demo); subscriptions are
hidden behind plans.js SUBSCRIPTIONS_ENABLED=false. Results become origin-transparent
(contract v2: every card names its `source`; X-OpenCITE-API-Version header).

Money path (closes v0.45 T3/T4 + audit P0/P1):
- webhook: fulfil packs only when payment_status is paid (+ async_payment_succeeded);
  pack buyers on `free` move to plan `machine`; charge.refunded / dispute claw the pack's
  credits back (clamped at 0); basil `line.pricing.price_details.price` invoice shape;
  P2002 catch scoped to the processed_events PK; customer id claimed only when null
- billing: applyMonthlyGrant is one atomic UPDATE (no lost concurrent increments);
  clawbackCredits; lazy 20-credit monthly grant for free users (apiAuth + /api/credits)
- search/meter: settle failures refund instead of escaping; 402 body carries
  code + upgrade_url; per-IP limiter BEFORE any DB touch; header-only keys with a
  format check; `;` terms capped at 5, q at 512 chars; empty adapter set -> 503 before
  pre-auth; circuit-open sources count as failed; coverage total 0 -> limited; `cite`
  + contract version in the cache key; caller mailto ignored on the metered path
- packs repriced cost-plus by changing credits per existing Stripe price:
  $10 -> 2,000 . $50 -> 12,000 . $200 -> 60,000; checkout collects ToS consent + billing
  address; PaymentIntent metadata carries the pack for reversals; idempotent customer create
